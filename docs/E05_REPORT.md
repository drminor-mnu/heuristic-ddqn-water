## 1. 실행 전 확인 사항 (완료)

### 1-1. E3 v2 "Regular"가 A0(ga_prob=0)와 같은 조건인가 — **아니오, 재사용 불가**

`results/E03_seeds/Regular/seed1/run_meta.json` 확인 결과 가중치
`[0.40,0.25,0.25,0.10]`·γ=0.7·split_seed=42는 A0과 일치하지만, **Regular는
`dqn_from_demon_v1.train()`을 통해 학습되었고, A1~A4가 전부 거치는
`_train_guided_by_optimizer()`와 구조가 다르다:**

| 항목 | `train()` (Regular) | `_train_guided_by_optimizer()` (A0~A4) |
|---|---|---|
| ε 스케줄 | 1.0 → (에피소드마다 −1/num_samples) → 바닥 0.2 | `eps_start`(0.3) → `eps_end`(0.05), 진행률(progress) 선형 |
| 리플레이 워밍업 | `len(replay) > batch_size`(20) | `len(replay) >= min_replay_size`(기본 100) |
| 타깃망 동기화 | 스텝 인덱스 `j % sync_freq`(10, 에피소드마다 리셋) | 누적 업데이트 횟수 `update_count % sync_freq`(200) |

세 가지 모두 다르다. **A0을 Regular로 재사용하면 "ga_prob" 외에 ε 스케줄·
리플레이 워밍업·동기화 방식까지 함께 바뀌어 단일변수 원칙이 깨진다.**
따라서 **A0은 재사용하지 않고 `_train_guided_by_optimizer(ga_start=0.0,
ga_end=0.0, eps_start=0.3, eps_end=0.05, sync_freq=200, min_replay_size=100,
...)`로 신규 실행한다** — A1~A4와 가이던스 확률 스케줄만 다르고 나머지는
전부 동일한 코드 경로를 taps.

### 1-4. 시드 정합성

`run_e05_ablation.py`의 기본값·실행 명령 모두 `--seeds 1,2,3`이며,
`run_e05_analyze.py`의 `SEEDS = [1, 2, 3]`이 A3(E3 v2 GA-guided) 재사용분도
동일하게 seed 1,2,3만 읽는다. **A0·A1(신규)과 A3(재사용)의 시드가
1,2,3으로 정확히 일치한다** — 별도 조정 불필요.

**주의(E3v2 seed4 제외 관련, `docs/E03_FINDINGS.md` §3.2~3.3 참조)**: E3 v2
GA-guided는 원래 5시드(1~5)로 실행되었고, dry-running risk-proxy가 시드별
`[3.83, 3.16, 2.74, 12.64, 1.99]`로 **seed4(12.64)가 뚜렷한 이상치**였다
(1440분 구간에서 seed4=76.0 vs 나머지 4시드 4.4~12.0 — E03_FINDINGS.md는
이를 "학습 발산이 아닌 동일 보상함수의 다른 국소최적으로의 안정 수렴"으로
규명했다). **A3가 seed 1,2,3만 쓰므로 이 변이(seed4)는 E5의 A3 표본에서
제외된다.** 이는 "빼고 유리하게 보고"가 아니라 **애초에 A0·A1(신규 3시드)과
표본 크기·시드값을 맞추기 위한 설계 선택**이며, E5의 3시드 결과는 E3
v2 공식 5시드 결과(`docs/E03_FINDINGS.md`)보다 dry-running 변동성이 낮게
나올 수 있다 — E5 결과를 E3 v2의 5시드 결론과 직접 병기할 때는 이 표본
차이를 명시해야 한다.

## 3. A1 구현이 A3와 다른 점 (명시 요구사항)

- **난수 소비량**: A3(GA)는 가이드가 호출될 때마다 개체군 초기화·토너먼트
  선택·교차·돌연변이로 다수의 `np.random` draw를 소비한다(개체수 100 ×
  세대수 최대 100). A1은 가이드 호출당 **정확히 1회**의 `np.random.randint`
  만 소비한다. 두 조건 모두 실행 시작 시 동일 시드로 `np.random.seed(seed)`
  하지만, **첫 가이드 호출 이후 두 런의 난수 스트림은 완전히 갈라진다** —
  이는 "지능적 탐색 vs 단순 무작위"라는 비교 대상 자체의 성질이며 결함이
  아니다.
- **가이드 확률·감쇠 스케줄**: A3와 **완전히 동일**(`ga_start=0.6,
  ga_end=0.0`, 같은 진행률 기반 선형 감쇠) — `_train_guided_by_optimizer`의
  기존 스케줄 계산 로직을 그대로 공유하므로 별도 구현 없이 보장됨.
- **objective_function 미사용**: A3는 가이드 호출 시 `objective_function`을
  다수 평가하지만(GA 탐색), A1은 상태·보상 구조를 전혀 보지 않는다 — 이것이
  Q1(지능적 선택 효과)이 측정하려는 바로 그 차이다.

## 7. 추가 분석 (학습 불필요, 이번 배치에서 수행)

### 7-1. 가이던스 액션의 시간적 상관 — 가장 중요

**먼저 확인한 사실**: 학습 중 "이 스텝이 가이던스에 의해 선택됐는가"를
스텝 단위로 기록한 로그는 **존재하지 않는다.** `train_log.csv`는
`episode, train_loss, train_reward` 세 열뿐이고, `_train_guided_by_optimizer`
내부에서 계산되는 에피소드 단위 `guided_count`도 **어떤 파일에도 저장되지
않는다**(표준출력에만 `{guide}_count: N`으로 찍히고 버려짐). 따라서
"가이던스가 개입한 스텝에 한정한" 지표를 학습 중 실제 액션 시퀀스에서
직접 뽑아낼 방법이 없다 — 재학습 없이는 복구 불가능한 정보다.

**대신 계산 가능한 두 가지**(둘 다 학습 없이, 저장된 체크포인트와 기존
휴리스틱 클래스만으로):

1. **가이드 단독(guide-only) 궤적**: `RandomGuide`/`GeneticAlgorithm`이
   매 스텝 스스로 결정하며 시나리오를 완주하는 궤적(기존
   `run_genetic_algo()`, 미변경). **이것은 학습 중 "가이던스가 개입한
   스텝"의 정확한 부분열이 아니다** — 학습 중에는 이력(`action_list`)이
   Q망·ε-탐욕·가이드가 뒤섞여 만든 실제 이력인 반면, guide-only 궤적은
   이력 전체가 그 가이드 자신이 만든 것이다. **"가이드 자신의 성질"에
   대한 근사치로만 쓴다.**
2. **학습된 정책 궤적**: 체크포인트로 `test_model()`(가이던스 없는 순수
   그리디 Q, §5-4와 동일 메커니즘) — 학습된 정책 자체의 성질.

측정 대상: 108개 층화 부표본(2/stratum, §5-4와 동일), 연속 동일 액션
run 길이(mean/median/p90), lag-1 상관(액션 인덱스를 수치로 취급 — 액션이
0~5 펌프 용량 사다리라는 순서형 구조를 가지므로 정당화됨), 스텝 간 변화율
P(a_t≠a_{t-1}).

**결과 — 5시드 최종** (2026-09-01 갱신: A0·A1·A3 학습정책 행 전부 5시드로

1. **가이드 단독 궤적은 극명하게 다르다.** RandomGuide-only는 run 길이

   108개(층화 부표본, 2/stratum)로 축소 — 시간 절감 목적, n 명시.
4. **단계 1 결과는 n=3시드로 어떤 지표도 통계적으로 유의하지 않다**(Wilcoxon
   n=3의 최소 가능 p=0.25, Holm 보정 후 전부 1.00). 계획서 요구사항(대응표본
   Wilcoxon+Cliff's δ+Holm)은 문면대로 수행했으나 **유의성 결론을 낼 수 있는

   §5의 답은 전부 "방향과 효과크기"까지만이고 "유의함"이라는 표현은 쓰지
   않았다.
5. **단계 2(A2)·단계 3(A4)은 취소되고 시드 확대(A0·A1 seed4,5 신규,
   A3·Regular 재사용 범위를 5시드로 확대)로 대체됨** — §6, 계획서 E5 절에
   반영. **완료(2026-09-01)**: A0·A1 seed4,5 학습 완료·무결성 확인, 4조건

### 계획과 달라진 점 (요지)
