# GA-only/PSO-only 액션 0 고착 — 원인 규명 및 파급효과

**작성일**: 2026-08-26
**착수 경위**: E0 5모델 스모크 테스트(3개 시나리오, 60분 지속시간)에서 GA-only/PSO-only가 매 스텝 액션 0(전량 정지)만 선택해 침수로 귀결됨을 관찰. "소규모 설정의 아티팩트일 수 있다"는 가설을 검증하기 위해 규모를 늘려 재조사함.

## 결론 (先)

**아티팩트가 아니다. 현재 가중치 (0.25, 0.40, 0.25, 0.10)와 `objective_function()`의 1-스텝 구조 하에서, GA/PSO는 수학적으로 언제나 액션 0을 최적으로 판정한다 — 수위·강우 조건과 무관하게.** 코드 버그가 아니라 목적함수 항 구성의 필연적 귀결이며, 재현 가능하고 결정적이다(무작위성과 무관).

> **⚠ 2026-08-28 정정 (§8 참조)**: 위 굵은 문장의 "수위·강우와 무관하게 언제나 액션 0"은 과한 서술이다. 정확히는 **직전 액션이 0일 때** 액션 0이 1위이며(→ 초기조건 `[0]`에서 시작하는 고정점 함정), 직전 액션이 비-0이면 목적함수는 펌프 유지를 선호한다. **§1·§2의 실측(GA-only 100% 고착·침수)은 그대로 유효**하다 — 평가 경로가 이력을 올바로 갱신함에도 첫 스텝을 벗어나지 못해 고착되기 때문. §3의 **원인 해석만** 수정된다.

## 3. 수학적 설명

`genetic_algo.py:71` `objective_function()`:

```
vol_reward = (actual_outflow / Σpumpq) * (next_level / Level_max)
act_reward = switching_stability(prev_action, act)   # 1 - (바뀐 펌프 수)/5
energy_reward = 1 - pump_rate / Σpumpq
reward = w1*vol_reward + w2*act_reward + w3*energy_reward + w4*(dry-run 페널티)
```

**액션 0(전량 정지)에서는 `actual_outflow=0`이므로 `vol_reward`가 항상 정확히 0이다** — 수위가 얼마나 높든 무관하게. 반면 `act_reward`와 `energy_reward`는 "펌프를 켜지 않음" 자체로 최댓값(각각 1)을 받는다. 가중치 (0.25, 0.40, 0.25, 0.10)에서:

- 액션 0의 점수 = `0*0.25 + 1*0.40 + 1*0.25 + 0*0.10 = 0.65` (상수, 강우·수위와 무관)
- 임의의 액션 a≠0으로 **처음** 전환할 때의 점수 = `w1*vol_reward(a) + w2*(switching cost) + w3*energy_reward(a)`. `vol_reward`의 이론적 최댓값은 2.0(유출량이 Σpumpq*2분을 가득 채우고 `next_level`이 최대치일 때)이므로 이 항의 최댓값 기여는 `0.25*2.0=0.5`. 그런데 액션을 전환하면 `switching_stability`가 즉시 깎이고(전량 정지→전체 가동이면 0으로), `energy_reward`도 펌프 용량에 비례해 깎인다. **가중치 조합 (0.25, 0.40, 0.25, 0.10)에서는 `w1`의 이론적 최댓값 기여(0.5)조차 액션 0의 상수 기준선(0.65)을 넘지 못한다** — 실측 표의 act1~act5 값(최대 0.6091)이 정확히 이를 확인해 준다.
- `w4`(dry-run 페널티) 항은 액션 0에서는 `attempted_outflow=0`이라 절대 발동하지 않으므로, "펌핑을 안 해서 침수돼도" 이 항으로는 전혀 벌점을 받지 않는다. **침수 자체를 직접 벌하는 항이 이 목적함수에 없다** — 펌핑을 "안 하면" 이득(`R_act`, `R_use`)이 있고 "하면" 즉시 손해가 나는 구조만 있을 뿐이다.

**이것은 코드 결함이 아니라 1-스텝(myopic) 목적함수의 구조적 성질이다.** `τ`(=`objective_function`)는 E2 감사(`docs/E02_ARGMINMAX.md`)가 이미 확인한 대로 "다음 스텝 보상의 1-스텝 예측치"일 뿐, 미래 누적 결과를 반영하지 않는다. GA/PSO는 매 결정 시점마다 이 1-스텝 점수만 보고 액션을 고르므로, "지금 펌프를 켜면 당장 손해, 나중에 침수를 막을 수 있다는 사실"을 절대 알 수 없다. 반면 DDQN(Regular 포함)은 TD-학습으로 벨만 방정식을 통해 미래 보상을 Q-값에 역전파하므로 같은 함정에 빠지지 않는다 — 스모크 테스트에서 Regular DDQN은 정상적으로 펌프를 가동했다(`results/E00_smoke/_E00smoke_regular_scenario_metrics.csv` 참조, n_switches>0).

## 4. 원고·기존 결과와의 충돌

`docs/RESULTS_PROVENANCE.md`는 `results/genetic_w0.25_w0.4_w0.25_w0.1_20260724.csv`가 논문 Table 11~16의 GA-only 행(최고수위 평균 **5.783m**, 침수 없음)과 정확히 일치한다고 "확인됨"으로 판정했다. 그러나 **현재 저장소의 `genetic_algo.py`(`objective_function()`)와 동일한 가중치(0.25/0.4/0.25/0.1)로 지금 실행하면, 모든 시나리오가 액션 0에 고착되어 최고수위 10m(침수)가 나온다** — 위 §1·§2가 그 증거다.

이 저장소는 2026-08-25 재투고 시점 스냅샷 커밋 이전의 git 이력이 없어(`git log --follow`로 `genetic_algo.py` 확인 시 커밋 1개뿐), 2026-07-24 실행 당시의 코드가 지금과 동일했는지 **버전관리로는 확인할 수 없다.** 세 가지 가능성이 남는다.

1. `objective_function()` 또는 관련 코드가 2026-07-24 이후 어떤 시점에 수정되어 지금과 달라졌다(직접 증거 없음, git 이력 부재로 배제 불가).
2. 2026-07-24 실행이 파일명과 다른 실제 가중치를 썼다(Table 8 복사 오류처럼 파일명 신뢰가 이미 한 번 깨진 전례가 있음).
3. 위 두 경우가 아니라면, 그 결과 자체의 재현성이 의심된다.

**어느 쪽이 맞는지는 이번 조사만으로 확정할 수 없다.** 다만 확실한 것은: **지금 이 코드로 GA-only를 다시 돌리면 원고 Table 11의 GA-only 값은 나오지 않는다.**

## 5. E3/E4/E9에 대한 함의

- **E3(다중 시드)**: 현재 코드 그대로 GA-only/PSO-only를 5시드 재학습·재평가하면, 원고 Table 11~15의 GA-only/PSO-only 행과는 판이하게 다른(침수 100%) 결과가 나올 가능성이 매우 높다. E3를 시작하기 전에 이 사실을 인지하고, "GA-only/PSO-only 결과가 원고와 크게 다르게 나올 수 있다"를 미리 반영해야 한다(계획서 지침 4항 — 불리한 결과를 그대로 기록).
- **E4(완전열거 baseline)**: 이번 발견은 E4가 다루려는 "1-스텝 근시안 목적함수의 한계"를 코드 수준에서 정량적으로 뒷받침하는 강력한 근거다. ENUM baseline도 같은 `objective_function()`을 완전열거로 평가하므로, **ENUM 역시 같은 이유로 액션 0에 고착될 것으로 예상된다** — 즉 "GA/PSO가 ENUM과 얼마나 일치하는가"(agreement rate)는 이 가중치에서 100%에 가깝게 나올 것이나, 그 일치가 곧 "좋은 정책과 일치"를 의미하지 않는다는 점을 명확히 해야 한다.
- **E9(보상-목적 정합성)**: 이 발견은 R1-4가 제기한 "단계별 보상 최대화가 시나리오 수준 목적 개선으로 이어지는가"에 대한 직접적이고 극단적인 반례다. 1-스텝 관점에서는 보상 극대화 정책(액션 0 고수)이 시나리오 목적(최고수위 최소화)을 정확히 반대로 악화시킨다.

## 6. 하지 않은 것

- `objective_function()` 또는 가중치를 수정하지 않았다 (리팩터링·결과 조정 금지 원칙).
- 2026-07-24 실행의 실제 코드/설정을 추가로 포렌식하지 않았다(git 이력 부재로 한계 명확).
- PSO-only에 대한 별도 30개 시나리오 재현은 수행하지 않았음 — PSO는 GA와 완전히 동일한 `objective_function()`을 상속해 쓰므로(`pso.py`, `ParticleSwarmOptimization(GeneticAlgorithm)`) 원인 구조가 동일할 것으로 판단해 생략. 필요 시 동일 절차로 확인 가능.

## 7. 확장 (2026-08-28): DDQN도 같은 함정에 빠진다 — 단, **4기준 보상 + gamma=0.1 조합**에 한함

E3 25회 실행 집계에서 **5개 모델 전부**(Regular / GA-guided / PSO-guided / GA-only / PSO-only)가
seed42 테스트 2,700 시나리오의 ~100%에서 월류함이 확인되었다(`results/summary/E03_*`).
GA-only/PSO-only의 붕괴는 위 §1~§3로 이미 설명되지만, **학습을 하는 DDQN(Regular 포함)까지
붕괴한 것**은 계획서 E3 배경이 예상하지 못한 부분이라 원인을 격리 실험으로 규명했다.

### 7.3 확인된 사실

1. **액션 0의 1-스텝 objective는 (직전 액션이 0일 때) 침수 상태에서도 상수 0.65로 최고** (§2~§3; §8 정정 — "직전 액션 0" 조건부이며 고정점 함정임).
2. **4기준 보상 + gamma=0.1이면 DDQN(Regular)도 같은 함정에 빠진다** — D0/D1에서 월류 100%, 액션0 고착 ~1.0. gamma=0.1은 유효 지평 ~1스텝이라 DDQN이 GA/PSO의 1-스텝 목적함수와 실질적으로 같은 근시안이 된다.
3. **가이던스로도 함정을 못 깬다** — 4기준+GA/PSO 가이던스가 30/30 시나리오에서 월류(진단 3b). 원고 Table 11~16의 GA-guided(5.607 m 비침수)·PSO-guided(5.637 m)는 현재 코드로 재현 불가.
4. **2기준 보상에서는 함정이 없다** — D6: 전 결함을 그대로 둔 채 가중치만 원고 2기준 [1,1,0,0]으로 바꾸자 월류 0, max_level 4.98(≈ 원고 Regular 5.495).
5. **gamma를 0.9로 올리면 액션 0 고착이 해소된다** — D2: 액션0 고착 0.97→0.00, 펌프 가동 244회. 다만 월류는 80% 잔존(gamma 단독으로는 불충분).
6. **정규화는 gamma를 고친 뒤에만 효과** — D1(정규화 단독) 무효, D4(정규화+gamma) 월류 0.15, D5(정규화+gamma+sync) 월류 0.

### 7.4 결론 (정정)

이것은 **"4기준 보상 설계 전체의 문제"가 아니라, 정확히는 "4기준 보상 + gamma=0.1 조합의 문제"다.**
D2에서 gamma=0.9만으로 액션 0 고착이 해소됐고 D5에서 월류 0이 나왔으므로, **4기준 보상 자체가
학습 불가능한 것은 아니다.** 이 구분이 중요하다 — 전자라면 방법론(보상 설계)을 바꿔야 하고,
후자라면 하이퍼파라미터(gamma, 정규화, sync)만 고치면 된다. 현재 증거는 **후자**를 가리킨다.

부수 사실:
- 원고(water-4498965)는 discount factor 값을 **명시하지 않았다**(Algorithm 3의 기호 γ로만 등장, 하이퍼파라미터 표 없음).
- 선행 논문(Joo et al. 2024) Table 7은 **γ = 0.4**로 명시하고, "낮은 γ가 최고수위 최소화에 유리"라고 결과로서 논의했다.
- 코드 `dqn_from_demon_v1.train()`은 `gamma = 0.1`을 하드코딩한다(`**params` 무시). 원고 미기재이자 선행값(0.4)과도 불일치하며, 근시안 방향으로 더 극단이다.
- target network sync: 선행 논문 "10 samples"(에피소드 단위)를 코드는 `j % 10`(에피소드 내 스텝 인덱스, 에피소드마다 리셋)으로 구현 — 의도보다 30~75배 잦음.

## 8. 정정 (2026-08-28): §3의 원인 해석 수정 — §1·§2의 실측은 유효

### 8.1 무엇이 바뀌고 무엇이 그대로인가

- **그대로 유효**: §1(30 시나리오 GA-only 전부 액션 0 고착·침수), §2(objective_probe 실측 수치). §1은 `evaluate_genetic_algo` → `GeneticAlgorithm.run_genetic_algo()` 경로로 얻었고, 이 경로는 **매 스텝 `action_list.append(action)`를 정확히 수행한다**(`genetic_algo.py:325,342`; PSO도 `pso.py:100`). 즉 §1의 고착은 올바른 액션 이력 하에서 재현된 결과이며 철회하지 않는다.
- **수정**: §3(및 결론 「先」·§7.3-1)의 **"수위·강우 조건과 무관하게 언제나 액션 0이 최적"이라는 서술은 과했다.** 정확히는 **"직전 액션이 0일 때, 1-스텝 objective는 첫 펌프 기동을 정당화하지 못한다"** 이며, 이는 초기조건 `action_list=[0]`에서 시작하는 **고정점(fixed point) 함정**이다. 목적함수는 상태에 무관한 것이 아니라 **직전 액션(`action_list[-1]`)에 의존**한다.

### 8.2 근거 — objective_function 재실측 (2026-08-28)

`objective_function`은 `action_list[-1]`(직전 액션)만 읽어 `act_reward = switching_stability(직전, 후보)`에 쓴다(`genetic_algo.py:87-92`). 동일 상태에서 직전 액션만 바꿔 6개 액션 점수를 실측(`50yr_0360m_h678`, 액션 3 유지 구동):

```
 step  level     vol | obj for prev=[0]                || obj for prev=[3]
                     |  a0    a1    a2    a3    a4    a5 ||  a0    a1    a2    a3    a4    a5
   40  4.700     0.0 | 0.65  0.57  0.49  0.28  0.13 -.02  (best a0) || 0.41  0.49  0.57  0.52  0.37  0.22  (best a2)
   80  7.726  7102.8 | 0.65  0.59  0.53  0.48  0.43  0.38 (best a0) || 0.41  0.51  0.61  0.72  0.67  0.62  (best a3)
  120  8.093  8989.8 | 0.65  0.59  0.54  0.48  0.44  0.40 (best a0) || 0.41  0.51  0.62  0.72  0.68  0.64  (best a3)
```

- `prev=[0]`: 모든 스텝에서 액션 0(0.65)이 1위 — §2 재현.
- `prev=[3]`: **펌프 유지(a3, 0.72)가 정지(a0, 0.41)를 이긴다.** switching_stability가 "직전과 동일" 유지를 보상하므로, 일단 펌프가 켜져 있으면 목적함수는 그것을 유지하는 쪽을 선호한다.

**따라서 액션 0 고착은 "목적함수가 상태를 무시해서"가 아니라, (1) 에피소드가 `action_list=[0]`으로 시작하고 → (2) prev=0에서 액션 0이 1위라 액션 0이 선택되며 → (3) 이력이 `[0,0,…]`로 유지되어 스스로 강화되는 고정점이기 때문이다.** GA-only 평가 경로는 이력을 올바로 갱신하지만, 첫 스텝에서 액션 0을 벗어나지 못하므로 이력이 계속 전부 0으로 유지되고, 결국 고착에서 빠져나오지 못한다 — §1의 결과가 그 귀결이다.

### 8.3 별개 사안 — guided 학습 루프의 `action_list` 미갱신 버그

`_train_guided_by_optimizer`(GA/PSO-guided **학습** 루프)는 `action_list = [0]`을 만든 뒤 **한 번도 갱신하지 않는다**(`dqn_from_demon_v1.py:517,557` — `append` 없음; 미사용 구버전 `train_guided_byGA_old`도 동일). 즉 guided 학습 중 GA/PSO는 매 스텝 **정적 `[0]`**을 직전 이력으로 받는다. 이는:

- **평가 경로(`run_genetic_algo`, `run_pso`)와 불일치** — 그쪽은 매 스텝 append 한다.
- **원고 Algorithm 3 line 27("Update x_t and L_a")과 불일치** — 원고는 이력 갱신을 명시한다.
- **효과**: guided 학습 중 GA/PSO가 "직전 = 전량 정지"로만 평가 → 액션 0을 실제 이력보다 더 강하게 추천 → 리플레이 버퍼에 액션 0 전이가 과다 유입 → guided DDQN의 액션 0 붕괴를 증폭한다.

이것은 §1(GA-only 평가)의 원인이 **아니다** — 평가 경로는 이력을 올바로 갱신하기 때문. 하지만 **E3의 guided 모델 붕괴에는 기여**하며, 원고 서술(Algorithm 3)에 맞추려면 고쳐야 한다. 수정 여부·범위·효과는 `results/_log/PROGRESS.md` 2026-08-28 항목과 리비전 판단에 따른다(코드는 아직 미수정, 진단은 env-gated 브랜치 `diag/e3-guided-realpath`에서 수행).
